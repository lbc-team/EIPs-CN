## 摘要

此 ERC 为 [ERC-721](./eip-721.md) 增加了一个市场功能，以实现非同质化代币交易，而无需依赖中介交易平台。与此同时，创作者可以实施更多样化的版税方案。

## 动机

目前大多数 NFT 交易依赖于充当中间人的 NFT 交易平台，这存在以下问题：

1. 通过 `setApprovalForAll` 函数授权会产生安全问题。授予 NFT 交易平台的权限暴露了不必要的风险。如果交易平台合约出现问题，将导致整个行业的重大损失。此外，如果用户授权交易平台处理他们的 NFT，这就允许网络钓鱼诈骗诱骗用户签署一条消息，允许诈骗者在 NFT 交易平台上以低价下单，并将自己指定为接收者。普通用户很难防范这一点。
2. 高交易成本是一个重要问题。一方面，随着交易平台数量的增加，NFT 的流动性变得分散。如果用户需要快速达成交易，他们必须在多个平台上授权和下单，这会增加风险暴露，并需要为每次授权支付额外的 gas 费。例如，以 BAYC 为例，总供应量为 10,000，目前持有者超过 6,000 人，每个持有者平均持有的 BAYC 不到 2 个。虽然 `setApprovalForAll` 可以节省在单个平台上挂单的 gas 费，但授权多个平台实际上会导致用户 gas 费用的总体增加。另一方面，交易平台收取的交易服务费也必须被视为交易成本，这通常远高于授权所需的 gas 费用。
3. 聚合器通过聚合流动性来提供解决方案，但决策过程是中心化的。此外，由于交易平台上的订单信息是链下的，聚合器获取数据的效率会受到交易平台 API 频率的影响，有时交易平台可能会暂停 API 的分发并限制其频率。
4. 项目方的版税收入依赖于 NFT 交易平台的中心化决策。一些交易平台在未经项目方同意的情况下实施可选版税，这侵犯了他们的利益。
5. NFT 交易平台不具备抗审查性。一些平台已经下架了大量的 NFT，而下架规则的制定和实施是中心化的，不够透明。过去，一些 NFT 交易平台出现故障，错误地将某些 NFT 下架，导致市场恐慌。

## 规范

本文档中的关键词 "MUST"（必须）、"MUST NOT"（禁止）、"REQUIRED"（必需）、"SHALL"（应）、"SHALL NOT"（不得）、"SHOULD"（应该）、"SHOULD NOT"（不应该）、"RECOMMENDED"（推荐）、"NOT RECOMMENDED"（不推荐）、"MAY"（可以）和 "OPTIONAL"（可选）应按照 RFC 2119 和 RFC 8174 中的描述进行解释。

符合规范的合约必须实现以下接口：

```solidity
interface IERC6105 {

  /// @notice 当一个代币被挂牌出售或下架时发出
  /// @dev 零 `salePrice` 表示该代币不出售
  ///      零 `expires` 表示该代币不出售
  /// @param tokenId - 被挂牌的代币的标识符
  /// @param from - 出售代币的地址
  /// @param salePrice - 代币的售价
  /// @param expires - UNIX 时间戳，买方可以在 expires 之前购买代币
  /// @param supportedToken - 支持的代币的合约地址或零地址
  ///                         零地址表示支持的代币是 ETH
  ///                         买方需要使用支持的代币购买商品
  /// @param benchmarkPrice - 额外的价格参数，可用于计算版税
  event UpdateListing(
    uint256 indexed tokenId,
    address indexed from,
    uint256 salePrice,
    uint64 expires,
    address supportedToken,
    uint256 benchmarkPrice
    );

  /// @notice 当一个代币被购买时发出
  /// @param tokenId - 被购买的代币的标识符
  /// @param from - 出售代币的地址
  /// @param to - 购买代币的地址
  /// @param salePrice - 代币的售价
  /// @param supportedToken - 支持的代币的合约地址或零地址
  ///                         零地址表示支持的代币是 ETH
  ///                         买方需要使用支持的代币购买商品
  /// @param royalties - 本次购买支付的版税金额
  event Purchased(
    uint256 indexed tokenId,
    address indexed from,
    address indexed to,
    uint256 salePrice,
    address supportedToken,
    uint256 royalties
    );

  /// @notice 创建或更新 `tokenId` 的挂牌信息
  /// @dev `salePrice` 必须不能设置为零
  /// @param tokenId - 被挂牌的代币的标识符
  /// @param salePrice - 代币的售价
  /// @param expires - UNIX 时间戳，买方可以在 expires 之前购买代币
  /// @param supportedToken - 支持的代币的合约地址或零地址
  ///                         零地址表示支持的代币是 ETH
  ///                         买方需要使用支持的代币购买商品
  /// 要求：
  /// - `tokenId` 必须存在
  /// - 调用者必须是代币的所有者、授权的操作员或批准的地址
  /// - `salePrice` 必须不能为零
  /// - `expires` 必须有效
  /// - 必须发出一个 {UpdateListing} 事件。
  function listItem(
    uint256 tokenId,
    uint256 salePrice,
    uint64 expires,
    address supportedToken
    ) external;

  /// @notice 创建或更新带有 `benchmarkPrice` 的 `tokenId` 的挂牌信息
  /// @dev `salePrice` 必须不能设置为零
  /// @param tokenId - 被挂牌的代币的标识符
  /// @param salePrice - 代币的售价
  /// @param expires - UNIX 时间戳，买方可以在 expires 之前购买代币
  /// @param supportedToken - 支持的代币的合约地址或零地址
  ///                         零地址表示支持的代币是 ETH
  ///                         买方需要使用支持的代币购买商品
  /// @param benchmarkPrice - 额外的价格参数，可用于计算版税
  /// 要求：
  /// - `tokenId` 必须存在
  /// - 调用者必须是代币的所有者、授权的操作员或批准的地址
  /// - `salePrice` 必须不能为零
  /// - `expires` 必须有效
  /// - 必须发出一个 {UpdateListing} 事件。
  function listItem(
    uint256 tokenId,
    uint256 salePrice,
    uint64 expires,
    address supportedToken,
    uint256 benchmarkPrice
    ) external;
 
  /// @notice 移除 `tokenId` 的挂牌信息
  /// @param tokenId - 被下架的代币的标识符
  /// 要求：
  /// - `tokenId` 必须存在并且正在挂牌出售
  /// - 调用者必须是代币的所有者、授权的操作员或批准的地址
  /// - 必须发出一个 {UpdateListing} 事件
  function delistItem(uint256 tokenId) external;
 
  /// @notice 购买代币并将其转移给调用者
  /// @dev `salePrice` 和 `supportedToken` 必须与预期的购买价格和代币匹配，以防止抢跑攻击
  /// @param tokenId - 被购买的代币的标识符
  /// @param salePrice - 代币的售价
  /// @param supportedToken - 支持的代币的合约地址或零地址
  /// 要求：
  /// - `tokenId` 必须存在并且正在挂牌出售
  /// - `salePrice` 必须与预期的购买价格匹配，以防止抢跑攻击
  /// - `supportedToken` 必须与预期的购买代币匹配，以防止抢跑攻击
  /// - 调用者必须能够支付 `tokenId` 的挂牌价格
  /// - 必须发出一个 {Purchased} 事件
  function buyItem(uint256 tokenId, uint256 salePrice, address supportedToken) external payable;

  /// @notice 返回 `tokenId` 的挂牌信息
  /// @dev 零售价表示该代币不出售
  ///      零 expires 表示该代币不出售
  ///      零支持代币地址表示支持的代币是 ETH
  /// @param tokenId 被查询的代币标识符
  /// @return 指定的挂牌信息（售价、过期时间、支持的代币、基准价格）
  function getListing(uint256 tokenId) external view returns (uint256, uint64, address, uint256);
}
```

## 原理

### 对某些局部变量的考虑

`listItem` 函数中的 `salePrice` 不能设置为零。首先，调用者将价格设置为 0 的情况很少发生，当发生时，通常是由于操作错误，这可能导致资产损失。其次，调用者需要花费 gas 来调用此函数，因此如果他可以将代币价格设置为 0，那么他此时的收入实际上为负，这不符合经济学中“经济人”的概念。此外，0 的代币价格表示该物品不出售，使参考实现更加简洁。

在 `listItem` 函数中设置 `expires` 允许调用者更好地管理他们的挂牌信息。如果挂牌信息自动过期，代币所有者将不再需要手动 `delistItem`，从而节省 gas。

在 `listItem` 函数中设置 `supportedToken` 允许调用者或合约所有者选择他们想要接受哪些代币，而不是仅限于单个代币。

`acceptCollectionOffer` 和 `acceptItemOffer` 函数中变量设置的基本原理与上述描述相同。

### 更多样化的版税方案

通过在 `listItem`、`acceptCollectionOffer` 和 `acceptItemOffer` 函数中引入参数 `benchmarkPrice`，可以将在 [ERC-2981](./eip-2981.md) 接口中的 `royaltyInfo(uint256 _tokenId, uint256 _salePrice)` 函数中的 `_salePrice` 更改为 `taxablePrice`，从而使 ERC-2981 版税方案更加多样化。以下是版税方案的几个示例：

`(address royaltyRecipient, uint256 royalties) = royaltyInfo(tokenId, taxablePrice)`

1. 增值版税（VAR，版税仅对卖方利润的一部分收费）：`taxablePrice=max(salePrice- historicalPrice, 0)`
2. 销售版税（SR）：`taxablePrice=salePrice`
3. 上限版税（CR）：`taxablePrice=min(salePrice, constant)`
4. 定量版税（QR，每个代币交易支付固定版税）：`taxablePrice= constant`

### 可选的黑名单

一些观点认为，应该阻止代币在不符合版税方案的中介市场上进行交易，但此标准仅提供了一种用于非中介 NFT 交易的功能，并且不提供标准化的接口来阻止代币在这些市场上进行交易。如果认为有必要更好地保护项目团队和社区的利益，他们可以考虑在其实现合约中添加黑名单，以防止 NFT 在不符合项目版税方案的平台上进行交易。

## 向后兼容性

此标准与 [ERC-721](./eip-721.md) 和 [ERC-2981](./eip-2981.md) 兼容。

## 参考实现

```solidity
 // SPDX-License-Identifier: CC0-1.0
pragma solidity ^0.8.8;
import "@openzeppelin/contracts/token/ERC721/ERC721.sol";
import "@openzeppelin/contracts/token/common/ERC2981.sol";
import "@openzeppelin/contracts/token/ERC20/IERC20.sol";
import "@openzeppelin/contracts/security/ReentrancyGuard.sol";
import "./IERC6105.sol";

/// @title 无中介 NFT 交易协议，具有增值版税
/// @dev 此参考实现使用的版税方案是增值版税
contract ERC6105 is ERC721, ERC2981, IERC6105, ReentrancyGuard{

  /// @dev 表示已挂牌出售代币的结构
  ///      零 `salePrice` 表示该代币不出售
  ///      零 `expires` 表示该代币不出售
  /// @param salePrice - 代币的售价
  /// @param expires - UNIX 时间戳，买方可以在 expires 之前购买代币
  /// @param supportedToken - 支持的 ERC20 代币的合约地址或零地址
  ///                         零地址表示支持的代币是 ETH
  ///                         买方需要使用支持的代币购买商品
  /// @param historicalPrice - 卖方上次购买此代币的价格
  struct Listing {
    uint256 salePrice;
    uint64 expires;
    address supportedToken;
    uint256 historicalPrice;
  }

  // 从代币 Id 到挂牌索引的映射
  mapping(uint256 => Listing) private _listings;

  constructor(string memory name_, string memory symbol_)
    ERC721(name_, symbol_)
    {
    }

  /// @notice 创建或更新 `tokenId` 的挂牌信息
  /// @dev `salePrice` 必须不能设置为零
  /// @param tokenId - 被挂牌的代币的标识符
  /// @param salePrice - 代币的售价
  /// @param expires - UNIX 时间戳，买方可以在 expires 之前购买代币
  /// @param supportedToken - 支持的 ERC20 代币的合约地址或零地址
  ///                         零地址表示支持的代币是 ETH
  ///                         买方需要使用支持的代币购买商品
  function listItem (
    uint256 tokenId,
    uint256 salePrice,
    uint64 expires,
    address supportedToken
    ) external virtual{
        listItem(tokenId, salePrice, expires, supportedToken, 0);
    }

  /// @notice 创建或更新带有 `historicalPrice` 的 `tokenId` 的挂牌信息
  /// @dev `price` 必须不能设置为零
  /// @param tokenId - 被挂牌的代币的标识符
  /// @param salePrice - 代币的售价
  /// @param expires - UNIX 时间戳，买方可以在 expires 之前购买代币
  /// @param supportedToken - 支持的 ERC20 代币的合约地址或零地址
  ///                         零地址表示支持的代币是 ETH
  ///                         买方需要使用支持的代币购买商品
  /// @param historicalPrice - 卖方上次购买此代币的价格
  function listItem (
    uint256 tokenId,
    uint256 salePrice,
    uint64 expires,
    address supportedToken,
    uint256 historicalPrice
    ) public virtual{

    address tokenOwner = ownerOf(tokenId);
    require(salePrice > 0, "ERC6105: token sale price MUST NOT be set to zero");  // 代币售价不能设置为零
    require(expires > block.timestamp, "ERC6105: invalid expires"); // 无效的过期时间
    require(_isApprovedOrOwner(_msgSender(), tokenId), "ERC6105: caller is not owner nor approved"); // 调用者不是所有者，也没有被授权

    _listings[tokenId] = Listing(salePrice, expires, supportedToken, historicalPrice);
    emit UpdateListing(tokenId, tokenOwner, salePrice, expires, supportedToken, historicalPrice);
  }

  /// @notice 移除 `tokenId` 的挂牌信息
  /// @param tokenId - 被挂牌的代币的标识符
  function delistItem(uint256 tokenId) external virtual{
    require(_isApprovedOrOwner(_msgSender(), tokenId), "ERC6105: caller is not owner nor approved"); // 调用者不是所有者，也没有被授权
    require(_isForSale(tokenId), "ERC6105: invalid listing" );  // 无效的挂牌信息

    _removeListing(tokenId);
  }

  /// @notice 购买代币并将其转移给调用者
  /// @dev `salePrice` 和 `supportedToken` 必须与预期的购买价格和代币匹配，以防止抢跑攻击
  /// @param tokenId - 被购买的代币的标识符
  /// @param salePrice - 代币的售价
  /// @param supportedToken - 支持的代币的合约地址或零地址
  function buyItem(uint256 tokenId, uint256 salePrice, address supportedToken) external nonReentrant payable virtual{
    address tokenOwner = ownerOf(tokenId);
    address buyer = msg.sender;
    uint256 historicalPrice = _listings[tokenId].historicalPrice;

    require(salePrice == _listings[tokenId].salePrice, "ERC6105: inconsistent prices"); // 价格不一致
    require(supportedToken ==  _listings[tokenId].supportedToken,"ERC6105: inconsistent tokens"); // 代币不一致
    require(_isForSale(tokenId), "ERC6105: invalid listing");  // 无效的挂牌信息

    /// @dev 处理版税
    (address royaltyRecipient, uint256 royalties) = _calculateRoyalties(tokenId, salePrice, historicalPrice);

    uint256 payment = salePrice - royalties;
    if(supportedToken == address(0)){
        require(msg.value == salePrice, "ERC6105: incorrect value"); // 不正确的价值
        _processSupportedTokenPayment(royalties, buyer, royaltyRecipient, address(0));
        _processSupportedTokenPayment(payment, buyer, tokenOwner, address(0));
    }
    else{
        uint256 num = IERC20(supportedToken).allowance(buyer, address(this));
        require (num >= salePrice, "ERC6105: insufficient allowance"); // 授权不足
        _processSupportedTokenPayment(royalties, buyer, royaltyRecipient, supportedToken);
        _processSupportedTokenPayment(payment, buyer, tokenOwner, supportedToken);
    }

    _transfer(tokenOwner, buyer, tokenId);
    emit Purchased(tokenId, tokenOwner, buyer, salePrice, supportedToken, royalties);
  }

  /// @notice 返回 `tokenId` 的挂牌信息
  /// @dev 零售价表示该代币不出售
  ///      零 expires 表示该代币不出售
  ///      零支持代币地址表示支持的代币是 ETH
  /// @param tokenId 被查询的代币标识符
  /// @return 指定的挂牌信息（售价、过期时间、支持的代币、基准价格）
  function getListing(uint256 tokenId) external view virtual returns (uint256, uint64, address, uint256) {
    if(_listings[tokenId].salePrice > 0 && _listings[tokenId].expires >=  block.timestamp){
    uint256 salePrice = _listings[tokenId].salePrice;
    uint64 expires = _listings[tokenId].expires;
    address supportedToken =  _listings[tokenId].supportedToken;
    uint256 historicalPrice = _listings[tokenId].historicalPrice;
    return (salePrice, expires, supportedToken, historicalPrice);
    }
    else{
      return (0, 0, address(0), 0);
    }
  }

  /// @dev 移除 `tokenId` 的挂牌信息
  /// @param tokenId - 被下架的代币的标识符
  function _removeListing(uint256 tokenId) internal virtual{
    address tokenOwner = ownerOf(tokenId);
    delete _listings[tokenId];
    emit UpdateListing(tokenId, tokenOwner, 0, 0, address(0), 0);
  }

  /// @dev 检查代币是否正在出售
  function _isForSale(uint256 tokenId) internal virtual returns(bool){
    if(_listings[tokenId].salePrice > 0 && _listings[tokenId].expires >= block.timestamp){
        return true;
    }
    else{
        return false;
    }    
  }
  
  /// @dev 处理增值版税
  function _calculateRoyalties(
    uint256 tokenId,
    uint256 price,
    uint256 historicalPrice
    ) internal virtual returns(address, uint256){
    uint256 taxablePrice;
    if(price > historicalPrice){
      taxablePrice = price - historicalPrice;
    }
    else{
      taxablePrice = 0 ;
    }

    (address royaltyRecipient, uint256 royalties) = royaltyInfo(tokenId, taxablePrice);
    return(royaltyRecipient, royalties);
  }

  /// @dev 处理支付给 `recipient` 的 `supportedToken` 的 `amount` 。
  /// @param amount - 要发送的金额
  /// @param from - 付款人
  /// @param recipient - 收款人
  /// @param supportedToken - 支持的 ERC20 代币的合约地址或零地址
  ///                         零地址表示支持的代币是 ETH
  function _processSupportedTokenPayment(
    uint256 amount,
    address from,
    address recipient,
    address supportedToken
    ) internal virtual{
    if(supportedToken == address(0))
    {
      (bool success,) = payable(recipient).call{value: amount}("");
      require(success, "Ether Transfer Fail"); // 以太币转移失败
    }
    else{
    (bool success) = IERC20(supportedToken).transferFrom(from, recipient, amount);
    require(success, "Supported Token Transfer Fail"); // 支持的代币转移失败
    }
  }
  
  /// @dev See {IERC165-supportsInterface}.
  function supportsInterface(bytes4 interfaceId) public view virtual override (ERC721, ERC2981) returns (bool) {
     return interfaceId == type(IERC6105).interfaceId || super.supportsInterface(interfaceId);
  }

  /// @dev 在转移 NFT 之前，需要删除挂牌信息
  function _beforeTokenTransfer(address from, address to, uint256 tokenId, uint256 batchSize) internal virtual override{
      super._beforeTokenTransfer(from, to, tokenId, batchSize);
      if(_isForSale(tokenId)){
          _removeListing(tokenId);
      }
  }
}
```

## 安全考虑

`buyItem` 函数以及 `acceptCollectionOffer` 和 `acceptItemOffer` 函数存在潜在的抢跑风险。必须检查 `salePrice` 和 `supportedToken` 是否与预期的价格和代币匹配，以防止抢跑攻击

`acceptCollectionOffer` 和 `acceptItemOffer` 函数存在潜在的重入风险。 确保遵守检查、效果、交互模式或使用重入保护。

如果买方使用 [ERC-20](./eip-20.md) 代币购买 NFT，则买方需要首先调用 ERC-20 代币的 `approve(address spender, uint256 amount)` 函数，以授予 NFT 合约访问一定 `amount` 的代币的权限。 请确保授权适当的 `amount`。 此外，建议在处理未经审计的合约时要谨慎。
