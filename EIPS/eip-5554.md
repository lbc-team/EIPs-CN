## 摘要

此 EIP 扩展了任何其他 token 标准，以提供：

* 与商业开发、衍生作品和复制相关的 token 持有者的明确权利；
* 用于创建、查看和检查许可证状态的 [EIP-5218](./eip-5218.md) 接口
* token 元数据中扩展许可证信息的标准格式；
* 用于跟踪衍生作品、商业开发和复制的链下创建的标准事件；
* 衍生作品和复制的链上跟踪
* 智能合约中引用版权所有者的其他必需字段
* 用于商业开发、衍生作品和复制的函数调用。

## 动机
NFT 仍然面临法律上的不确定性，现在许多人意识到与 NFT 相关的权利与 NFT 本身同样重要。我们的目标是帮助生态系统就 NFT 购买者在版权或其他权利方面获得的内容达成明确共识和广泛理解。

今天，购买数字作品的 NFT 与购买该作品的版权不同。在大多数情况下，NFT 甚至不包含数字作品；它仅通过哈希引用它。因此，NFT 持有者拥有该作品的唯一数字副本，但不一定享有复制、重新分发或以其他方式利用该作品的权利——除非版权所有者明确规定。它通常仅包括私人欣赏作品并在社交媒体或虚拟画廊中公开展示的权利。

我们的目标是创建一套新的具有模块化条款和条件的许可证——类似于 Creative Commons——以便艺术家可以通过将额外的权利与它们相关联来提高其 NFT 的价值（例如，创建衍生作品的权利，或允许对基础作品进行商业使用）。我们的解决方案将允许授予任何许可权利，仅且专门授予 NFT 的当前持有者，并在每次 NFT 被转移时自动转移给新的 token 持有者。

受版权保护材料的链上注册将有助于发现与使用此协议创建的 NFT 相关的权利。

我们目前的工作是起草法律条款和技术规范。

## 规范
本文档中的关键词“MUST”、“MUST NOT”、“REQUIRED”、“SHALL”、“SHALL NOT”、“SHOULD”、“SHOULD NOT”、“RECOMMENDED”、“MAY”和“OPTIONAL”应按照 RFC 2119 中的描述进行解释。

每个符合此 EIP 的合约都必须实现 `IERC5554` 接口：

```solidity
pragma solidity ^0.8.0;

interface IERC5554 is IERC5218 {

    event CommercialExploitation(uint256 _tokenId, uint256 _licenseId, string _externalUri);
    event ReproductionCreated(uint256 _tokenId, uint256 _licenseId, uint256 _reproductionId, address _reproduction, uint256 _reproductionTokenId);
    event DerivativeCreated(uint256 _tokenId, uint256 _licenseId, uint256 _derivativeId, address _derivative, uint256 _derivativeTokenId);

    /// @notice 检索版权所有者地址
    /// @dev 抛出异常，除非 token 存在
    /// @param tokenId 查询的 token 的标识符
    /// @return 版权所有者的地址
    function getCopyrightOwner(uint256 tokenId)
        external
        virtual
        returns (address);
    
    /// @notice 请求记录许可证的执行情况
    /// @dev 抛出异常，除非满足 token 发行条件
    /// @param tokenId 查询的 token 的标识符
    /// @return uint256 跟踪复制 ID
    function logReproduction(uint256 tokenId, address reproduction, uint256 reproductionTokenId)
        external
        virtual
        returns (uint256);

    /// @notice 请求记录许可证的执行情况
    /// @dev 抛出异常，除非满足 token 发行条件
    /// @param tokenId 查询的 token 的标识符
    /// @return uint256 跟踪衍生品 ID
    function logDerivative(uint256 tokenId, address derivative, uint256 derivativeTokenId)
        external
        virtual
        returns (uint256);

    /// @notice 请求记录许可证的执行情况
    /// @dev 抛出异常，除非满足商业开发条件
    /// @param tokenId 查询的 token 的标识符
    function logCommercialExploitation(uint256 tokenId, string calldata uri)
        external;

    /// @notice 检索与复制关联的 token
    /// @dev 抛出异常，除非复制存在
    /// @param _reproductionId 复制的标识符
    /// @return uint256 用于生成复制的 token 的标识符
    function getReproductionTokenId(uint256 _reproductionId)
        external
        view
        returns (uint256);

    /// @notice 检索与复制关联的 token
    /// @dev 抛出异常，除非复制存在
    /// @param _reproductionId 复制的标识符
    /// @return uint256 用于生成复制的许可证的标识符
    function getReproductionLicenseId(uint256 _reproductionId)
        external
        view
        returns (uint256);

    /// @notice 检索与复制关联的 token
    /// @dev 抛出异常，除非复制存在
    /// @param _reproductionId 衍生作品的标识符
    /// @return address 复制集合的地址
    function getReproductionCollection(uint256 _reproductionId)
        external
        view
        returns (address);

    /// @notice 检索与衍生品关联的 token
    /// @dev 抛出异常，除非衍生品存在
    /// @param _derivativeId 衍生作品的标识符
    /// @return uint256 用于生成衍生作品的 token 的标识符
    function getDerivativeTokenId(uint256 _derivativeId)
        external
        view
        returns (uint256);

    /// @notice 检索与衍生品关联的 token
    /// @dev 抛出异常，除非衍生品存在
    /// @param _derivativeId 衍生作品的标识符
    /// @return uint256 用于生成衍生作品的许可证的标识符
    function getDerivativeLicenseId(uint256 _derivativeId)
        external
        view
        returns (uint256);

    /// @notice 检索与衍生品关联的 token
    /// @dev 抛出异常，除非衍生品存在
    /// @param _derivativeId 衍生作品的标识符
    /// @return address 衍生品集合的地址
    function getDerivativeCollection(uint256 _derivativeId)
        external
        view
        returns (address);

}
```

## 理由
我们在此扩展动机部分，以证明就标准规范所做的每个决定的合理性：

`getLicenseId()` 函数采用 tokenID 作为参数，从而可以使不同的 tokenID 与不同的许可条款相关联。

LicenseURI 链接到内容寻址文件，该文件规定了实际法律语言中的许可条款和条件，以便那些想要了解哪些权利与作者的作品相关联以及通过通过获取 NFT 授予了哪些其他权利的人可以阅读和理解该许可。

当许可仅允许 token 持有者复制和/或创建衍生作品时，需要一种方法来验证新的 NFT 或衍生 NFT 是否是合法创建的。该标准通过使当前 token 持有者能够调用一个函数（例如 logDerivative，该函数检查调用者是否具有执行的有效许可证）来确保这一点。

对于商业开发或创造性作品的其他链下使用，该标准实施了 `logCommercialExploitation()`，该函数可以跟踪已进行的商业开发以及何时进行的商业开发。这使得可以验证所有商业开发是否都是合法完成的。

该标准引入了一个新字段 `copyrightOwner`，它指示作品中版权的当前持有者的地址。如果存在多个版权所有者，则可以使用多重签名地址（或 DAO）。

艺术家地址未注册为链上变量，而是作为元数据的一部分，因为它是一个不可变的字段。

如果存在，作品的父项（即其衍生的作品）必须是元数据信息的一部分，以便人们可以验证 NFT 是否已获得每个父项的 DerivativeWork。

此许可框架旨在创建一个系统，以通过公共许可框架促进“跟随 token”的权利许可。这不适用于通过个人许可向特定参与者授予专有权（例如，版权所有者授予第三方商业开发作品的权利，无论他们是否持有 token）的情况。它也并非旨在考虑再许可情况（例如，许可一方许可第三方从事商业开发的权利），因为这应该通过个人版权许可计划来完成。


### 示例

#### Bored Koalas 商品

Vigdís 创建了一个 Bored Koalas 的 PFP 集合，该集合受标准版权限制的约束：任何人均无权复制、分发、传播、商业化或混音这些作品。但是，她想向持有该集合 NFT 的人授予特定权限。她使用此 EIP 铸造了该集合，引入了一个有条件的许可，该许可允许当前的 token 持有者展示与每个 NFT 关联的 Bored Koala，并将其商业化仅用于商品销售。

Neža 购买了其中一只 Bored Koala。她想制作商品以在其区块链会议上分发。她去了一家印刷店，请他们制作 T 恤，上面印有她购买的 NFT 的 Bored Koala 图像。印刷店可以通过验证他们是 Bored Koala NFT 的持有者并验证与之相关的许可条款来验证她是否具有商业开发作品的权利。（注意：这不需要授予印刷店分许可，因为商业开发意味着委托第三方从事此类商业开发）。Neža 将 T 恤带到她的会议上并出售。在这样做时，她从 NFT 智能合约中调用 `logCommercialExploitation()` 函数，以便跟踪商业开发是在她担任 token 持有者时完成的。

#### 音乐混音

Matti 是新兴的 web3 音乐生态系统中一位崭露头角的词曲作者。在即将举行的加密货币会议上，他创作了一首名为“Degens in the Night”的热门歌曲。Matti 没有在 web2 平台上列出这首歌，而是使用此 EIP 将这首歌铸造为 NFT，采用双重许可方案：一项通用公共许可，允许在适当署名的情况下免费复制和重新分发作品（例如，Creative Commons BY-NC-ND）以及一项有条件的许可，允许 token 持有者混音这首歌，以换取特定的总额（例如，1ETH），并且前提是衍生作品以与原始作品相同的许可条款发布。Lyyli 想要为这首歌创建一个翻唱版本，她称之为“Degens in the Parisian Night”。她购买了 NFT，并使用此 EIP 标准在新的智能合约下铸造了一个新的衍生 NFT。然后，她调用 `requestDerivativeToken()` 函数并将 1ETH 发送到原始 NFT 智能合约，以便请求将 DerivativeToken 分配给她创建的新智能合约。智能合约自动批准将 Derivative Token 分配给 Lyyli 的新智能合约的请求。这可以用作衍生作品实际上是合法作品的证明，该作品已获得原始作品的版权所有者的批准。在会议期间，数百名其他 web3 音乐创作者举办了一个附带活动，播放“Degens in the Night”混音直到凌晨 4 点。

#### 版税混音

Alice 创建了一个摩托车的 3D 模型，她希望每个人都进行混音，条件是她从所有衍生作品的商业开发中获得版税。她使用此 EIP 将她的作品作为 NFT 发布，该 EIP 采用双重许可方案：一项通用公共许可，允许在适当署名的情况下免费复制和重新分发作品（例如，Creative Commons BY-NC-ND）以及一项有条件的许可，允许 token 持有者混音这首歌，条件是衍生作品以与原始作品相同的许可条款发布，并且他和混音者之间存在版税分成。

Jane 想要创建摩托车的衍生作品。她购买了 NFT，并在一个新的智能合约下铸造了一个新的衍生 NFT，该合约使用此 EIP，其中包括 Alice 的版税分成。然后，她从原始 NFT 智能合约中调用 `requestDerivativeToken()` 函数，以便请求将 DerivativeToken 分配给她创建的新智能合约。Alice 决定智能合约不应自动批准或拒绝该请求，而是等待她验证或使该请求无效，在此之后，她已验证了新智能合约的设计和规定，即它确实复制了与原始作品相同的条款和条件，并且它包含了适当数量的版税。她批准将 Derivative Token 分配给 Jane 的新智能合约的请求。当人们购买 Jane 的 NFT 时，版税会被分割，以确保将产生的利润正确地重新分配给 Alice。
