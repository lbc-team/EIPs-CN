## 摘要

此 EIP 定义了用于引导以太坊网络的以太坊 genesis 文件 (`genesis.json`) 的规范结构。该标准与 Geth (Go-Ethereum) 实现的事实结构相一致，并且已被其他客户端采用。它引入了一个 JSON Schema，以确保客户端之间的一致性和工具兼容性。

## 动机

由于缺乏 `genesis.json` 文件的官方标准，导致了不兼容、错误和混乱，以及增加了在测试网络中一起运行多个客户端的工作量。本 EIP 旨在通过定义一致的结构并通过基于 schema 的验证启用工具来减少歧义。

## 规范

规范的 genesis 文件必须是一个 JSON 对象，包含以下顶级字段：

### 顶级字段

| 字段          | 描述                                                         |
|---------------|--------------------------------------------------------------|
| `config`      | 链配置对象。                                                 |
| `alloc`       | 地址到预分配余额和/或代码/存储的映射。                       |
| `nonce`       | 十进制或十六进制 nonce。                                     |
| `timestamp`   | 十进制或十六进制 UNIX 时间戳。                               |
| `extraData`   | 任意的额外数据。                                             |
| `gasLimit`    | 十进制或十六进制区块 gas 限制。                              |
| `difficulty`  | 十进制或十六进制区块难度。                                   |
| `mixhash`     | 十六进制的 mix hash。                                        |
| `coinbase`    | 十六进制地址。                                               |

### `config` 对象

`config` 对象包含硬分叉激活区块号和分叉配置。已知的键包括：

| 字段                      | 描述                                                                           |
|---------------------------|--------------------------------------------------------------------------------|
| `chainId`                 | 区块链的唯一标识符。                                                             |
| `<hardfork(Block\|Time)>` | 激活命名硬分叉的区块高度或时间戳。                                             |
| `terminalTotalDifficulty` | 从 PoW 切换到 PoS 后的难度。                                                    |
| `depositContractAddress`  | 存款合约的以太坊地址                                                           |
| `blobSchedule`            | 硬分叉及其 EIP-4844 DAS [配置参数](eip-7840.md) 的映射。                       |

### `blobSchedule` 对象

| 字段                    | 描述                               |
|-------------------------|------------------------------------|
| `target`                | 每个区块要包含的期望的 blob 数量     |
| `max`                   | 每个区块要包含的最大 blob 数量     |
| `baseFeeUpdateFraction` | 每个 EIP-4844 的定价公式的输入    |

### `alloc` 对象

`alloc` 字段定义了 genesis 时的初始状态。它将地址（作为小写的十六进制字符串）映射到以下对象：

| 字段        | 描述                                        |
|-------------|---------------------------------------------|
| `balance`   | 以 wei 为单位的十进制余额。                  |
| `code`      | 十六进制编码的 EVM 字节码。                   |
| `nonce`     | 十进制或十六进制值。                        |
| `storage`   | 表示初始存储的键值十六进制映射。            |

```json
      "type": "string",

    }
  },
  "title": "Ethereum Genesis File",

  "required": ["alloc", "gasLimit", "difficulty"],

        "chainId": { "type": "integer" },
        "homesteadBlock": { "type": "integer" },
        "daoForkBlock": { "type": "integer" },
        "eip150Block": { "type": "integer" },
        "tangerineWhistleBlock": {"type":  "integer"},
        "eip155Block": { "type": "integer" },
        "spuriousDragonBlock": {"type": "integer"},
        "byzantiumBlock": { "type": "integer" },
        "constantinopleBlock": { "type": "integer" },
        "petersburgBlock": { "type": "integer" },
        "istanbulBlock": { "type": "integer" },
        "muirGlacierBlock": {"type": "integer"},
        "berlinBlock": { "type": "integer" },
        "londonBlock": { "type": "integer" },
        "arrowGlacierBlock": { "type": "integer" },
        "grayGlacierBlock": { "type": "integer" },
        "terminalTotalDifficulty": { "type": "integer" },
        "mergeNetsplitBlock": { "type": "integer"},
        "shanghaiTime": { "type": "integer"},
        "cancunTime": { "type": "integer"},

        "depositContractAddress": { "$ref": "#/$defs/address"},

          "additionalProperties": {

    "timestamp": { "$ref": "#/$defs/hexOrDecimal48" },

      "anyOf": [
        {"type": "string", "const": "" },
        {"type": "string", "pattern": "^0x([0-9a-fA-F]{2})*$" }
      ]
    },
    "gasLimit": { "$ref": "#/$defs/hexOrDecimal48" },
    "difficulty": { "$ref": "#/$defs/hexOrDecimal48" },
    "mixhash": { "$ref": "#/$defs/hash" },
    "coinbase": { "$ref": "#/$defs/address" },
    "alloc": {
      "type": "object",
      "patternProperties": {
        "^(0x)?[0-9a-fA-F]{40}$": {
          "type": "object",
          "properties": {
            "balance": { "$ref": "#/$defs/hexOrDecimal" },
            "nonce": { "$ref": "#/$defs/hexOrDecimal48" },
            "code": { "type": "string", "pattern": "^0x([0-9a-f])*$" },
            "storage": {
              "type": "object",
              "patternProperties": {
                "^0x[0-9a-f]{64}$": {
                  "$ref": "#/$defs/hash"
                }
              }
            }
          }
        },
        "additionalProperties": false
      },
      "additionalProperties":false
    }
  },
  "additionalProperties": true
}

```

## 理由

越来越多的 EIP 提出了改进 genesis 时网络配置的方法：

[向 EL 配置文件添加 Blob Schedule](eip-7840)

[仅 Blob 参数的硬分叉](eip-7892)

[eth_config JSON-RPC 方法](eip-7910)

然而，这些修改的根配置元素仍未指定。采用最小 schema 来定义它将使后续更改更加准确和简洁。

## 安全考虑

由于这是一个可选的信息性 EIP，仅提供开发者便利，并且必须与节点的管理员访问权限一起使用，因此不会引入新的安全问题。
