## 摘要

本规范定义了识别控制合约的帐户所需的最小接口。

## 动机

这是 [EIP-173](./eip-173.md) 的简化替代方案。

## 规范

本文档中的关键词“必须”应按照 RFC 2119 中的描述进行解释。

每个符合此 EIP 的合约都必须实现 `EIP5313` 接口。

```solidity
// SPDX-License-Identifier: CC0-1.0
pragma solidity ^0.8.15;

/// @title EIP-5313 轻量级合约所有权标准
interface EIP5313 {
    /// @notice 获取所有者的地址
    /// @return 所有者的地址
    function owner() view external returns(address);
}
```

## 理由

影响该标准的主要因素：

- 最小化接口中的函数数量
- 与现有合约的向后兼容性

该标准可以（并且已经被）其他标准扩展，以添加额外的所有权功能。 本规范的较小范围允许更多更直接的所有权实现，请参阅 EIP-173 中“考虑过的其他方案”下解释的限制。

实现 [EIP-165](./eip-165.md) 可能是对该接口规范的宝贵补充。 但是，编写此 EIP 是为了编纂将合约（通常是 NFT）与第三方网站（通常是众所周知的 NFT 市场）连接起来的现有协议。

## 向后兼容性

每个实现 EIP-173 的合约都已经实现了此规范。

## 安全注意事项

由于此规范没有扩展 EIP-165，因此调用此 EIP 的 `owner` 函数不能完全确定结果确实是所有者。 例如，具有相同函数签名的另一个函数可能会返回一些值，然后将其解释为真正的所有者。 如果此 EIP 仅用于识别帐户是否为合约的所有者，则可以最大程度地减少此风险的影响。 但是，如果审问者例如将有价值的 NFT 发送到网络上任何合约的已识别所有者，则风险会增加。
