## 摘要

一组函数，用于通过符合 [EIP-712](./eip-712.md) 类型消息签名规范的签名，实现元交易和与实现操作员模型的合约的原子交互。

## 动机

此标准的主要动机是增强操作员管理的灵活性、安全性和效率。通过利用 EIP-712 签名，此标准允许用户授权操作员，而无需链上交易，从而降低 gas 成本并改善用户体验。这在需要频繁的操作员更改和跨链交互时尤其有益。

此外，此标准旨在：

1. **启用元交易**：允许用户将交易的执行委托给操作员，从而启用元交易，其中用户无需持有原生代币来支付每个链上的 gas 费用。
2. **提高安全性**：利用 EIP-712 标准进行类型化数据签名，与原始数据签名相比，这提供了一种更安全且用户友好的消息签名方式。
3. **促进互操作性**：为操作员管理提供标准化的接口，该接口可以被各种 vault 协议采用，从而促进互操作性并降低开发人员的集成复杂性。
4. **简化跨链操作**：简化跨不同链管理操作员的过程，使协议更容易在多链环境中维护一致的操作员权限和交互。

通过满足这些需求，`Authorize Operator` 标准旨在简化去中心化 vault 协议中操作员管理的过程，使用户和开发人员能够以安全、经济高效且可在多个区块链网络上互操作的方式与智能合约进行交互。

## 规范

### 操作员兼容合约

此签名授权方案适用于实现以下接口的任何合约：

```solidity
  interface IOperator {
    event OperatorSet(address indexed owner, address indexed operator, bool approved);

    function setOperator(address operator, bool approved) external returns (bool);
    function isOperator(address owner, address operator) external returns (bool status);
  }
```

[EIP-6909](./eip-6909.md) 和 [EIP-7540](./eip-7540.md) 已经实现了这个接口。

参数的命名是可以互换的，例如 [EIP-6909](./eip-6909.md) 使用 `spender` 而不是 `operator`。

### 方法

#### `authorizeOperator`

使用 [EIP-712](./eip-712.md) 签名，授予或撤销 `operator` 代表 `msg.sender` 管理请求的权限。

如果 `deadline` 已过，则必须恢复。

必须使签名的 nonce 无效，以防止消息重放。

如果 `signature` 不是具有给定输入参数的有效 [EIP-712](./eip-712.md) 签名，则必须恢复。

必须将操作员状态设置为 `approved` 值。

必须记录 `OperatorSet` 事件。

必须返回 `true`。

```yaml
- name: authorizeOperator
  type: function
  stateMutability: nonpayable

  inputs:
    - name: owner
      type: address
    - name: operator
      type: address
    - name: approved
      type: bool
    - name: nonce
      type: bytes32
    - name: deadline
      type: uint256
    - name: signature
      type: bytes

  outputs:
    - name: success
      type: bool
```

#### `invalidateNonce`

撤销作为 `owner` 的 `msg.sender` 的给定 `nonce`。

```yaml
- name: invalidateNonce
  type: function
  stateMutability: nonpayable

  inputs:
    - name: nonce
      type: bytes32
```

#### `authorizations`

返回给定的 `nonce` 是否已用于 `controller`。

```yaml
- name: authorizations
  type: function
  stateMutability: nonpayable

  inputs:
    - name: controller
      type: address
    - name: nonce
      type: bytes32
  outputs:
    - name: used
      type: bool
```

#### `DOMAIN_SEPARATOR`

返回根据 EIP-712 定义的 `DOMAIN_SEPARATOR`。`DOMAIN_SEPARATOR` 对于合约和链应该是唯一的，以防止来自其他域的重放攻击，并满足 EIP-712 的要求，但在其他方面不受约束。

```yaml
- name: DOMAIN_SEPARATOR
  type: function
  stateMutability: nonpayable

  outputs:
    - type: bytes32
```

### [ERC-165](./eip-165.md) 支持

实现此标准的智能合约必须实现 [ERC-165](./eip-165.md) `supportsInterface` 函数。

如果通过 `interfaceID` 参数传递 `0xa9e50872`，则合约必须返回常量值 `true`。

## 理由

### 类似于 [ERC-2612](./eip-2612.md)

该规范经过有意设计，与 [ERC-2612](./eip-2612.md) 非常匹配。这应该简化标准的新集成。

主要区别在于使用 `bytes32` 与 `uint256`，这支持无序 nonce。

## 安全考虑

操作员对用户拥有重要的控制权，并且签名的消息可能导致不良结果。到期日期应尽可能短地设置，以减少未使用的签名在稍后泄漏的可能性。
