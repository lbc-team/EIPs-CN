## 摘要

这是一个提议，添加一个新的操作码 `GETCONTRACT`。`GETCONTRACT` 操作码将通过哈希返回包含字节码的地址。

## 动机

通过哈希寻址内容是数据库设计中的一种常见模式。它允许通过其在存储中的唯一足迹来存储和检索数据。这种模式在工业界被广泛使用，它允许抽象出实际的存储位置，并允许在多个合约中重用相同的字节码。

如今，现有的合约发现依赖于地址，而地址是不确定的，并且可以通过代理进行混淆。通过字节码哈希进行索引提供了一种确定性和防篡改的方式来识别和验证合约代码，从而增强以太坊生态系统中的安全性和信任。

考虑一位想要证明合约代码完整性的安全审计员。通过引用字节码哈希，审计员可以将他们的审计重点放在字节码本身上，而无需评估部署参数或存储内容。此方法验证合约代码库的完整性，而无需审计整个合约状态。

此外，字节码引用允许在部署之前将合约列入白名单，允许开发人员在不公开代码本身的情况下获得其代码库的预先批准，甚至可以预先设置基础设施，这些基础设施将在链上添加某些确定的功能后改变其行为。

对于依赖于大量代码重用的开发人员来说，字节码引用可以防止通过代理基于地址的引用可能发生的恶意更改。这构建了延伸到最终用户应用程序的长期信任链。

对于去中心化应用程序 (dApp) 开发人员来说，代码索引可以通过允许他们引用现有代码库而不是重新部署它们来节省 gas 成本，从而优化资源使用。这对于依赖于大量重用相同代码库作为自身依赖项的 dApp 来说非常有用。

这也允许更方便地构建新的核心标准，例如，[EIP-7702](./eip-7702) 可以将其用作依赖项，以允许想要在其 EOA 上设置一次性代码的用户通过引用 `GETCONTRACT` 而不是指定可能易变的基于地址的功能性来实现。

## 规格

### 操作码定义

* **助记符:** `GETCONTRACT`
* **操作码值:** `0x4f`
* **输入:**
    * `codehash`: 来自堆栈的单个 32 字节代码哈希。
* **输出:**
    * `address`: 如果 `codehash` 存在于状态中，则将相应的合约地址推送到堆栈上。否则，推送 0。
* **Gas 成本:** 150
* **堆栈影响:** 弹出 1 个项目，推送 1 个项目。
* **错误处理:** 如果 `codehash` 无效或字节码检索遇到错误，则指令将回退。

EVM 中存储的每个合约**必须**添加到状态树中，密钥是合约字节码的 keccak256 哈希，前提是：

* 尚未存在
* 合约未调用 `SELFDESTRUCT` 操作码。
* `EXTCODEHASH` 返回值**不是** `0xeadcdba66a79ab5dce91622d1d75c8cff5cff0b96944c3bf1072cd08ce018329` (`keccak256(0xef01)`)

### 用法示例

```solidity
function getContractAddress(bytes32 codehash) public view returns (address) {
    address contractAddress;
    assembly {
        contractAddress := GETCONTRACT(codehash)
    }
    return contractAddress;
}
```

## 理由

**字节码优先于地址**: 字节码是确定性的，可以在链上验证，而地址是不透明且可变的。

**不要重新索引**: 哈希冲突攻击的可能性很小，但并非为零。不允许更新字节码的索引位置会消除这种情况。

**Gas 成本**: 此操作比简单的数据检索更复杂，但是通过哈希在数据库中查找通常在复杂性上更简单。

## 安全考虑

**恶意代码**: 索引**不**保证索引合约的安全或功能。用户**必须**谨慎行事，并在与索引合约交互之前进行自己的尽职调查。

**已注册合约的存储内容**: 索引仅指合约的字节码，而不指存储内容。这意味着合约状态未被索引，并且可能会随着时间的推移而变化。

**[EIP-7702](./eip-7702) 委托:** 禁止临时代码委托，以防止注册无法使用的代码哈希的情况。标准明确禁止使用通过 [EIP-7702](./eip-7702) 委托的字节码的合约被索引。

**SELFDESTRUCT**: `selfdestruct` 的合约不会被索引，因为它们在状态树中没有 codehash。
