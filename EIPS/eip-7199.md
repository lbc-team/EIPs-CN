## 摘要

目前在实践中，EIP linter 工具（例如 EIPW）会阻止一个 Pull Request，即使该 lint 错误不是在该 Pull Request 中引入的。
此 EIP 明确指出，除非更改 EIP 的状态，否则未触及行的 lint 错误应被视为可忽略的。

## 规范

本文档中的关键词“MUST”，“MUST NOT”，“REQUIRED”，“SHALL”，“SHALL NOT”，“SHOULD”，“SHOULD NOT”，“RECOMMENDED”，“MAY”和“OPTIONAL”应按照 RFC 2119 中的描述进行解释。

在更新 EIP 时，不应要求 Pull Request 修复未触及行中的 linter 错误，除非它正在更改 EIP 的状态。

## 理由

此策略允许任何人进行微贡献，他们只想修复大型 EIP 中的拼写错误或更改某个部分。
