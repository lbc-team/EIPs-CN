## 简述

作为以 EIP 为中心的 fork 模型的一部分，此 EIP 跟踪任何 EIP 包含在 fork 或升级中的审批过程的第一步。 具体来说，核心开发者审查 EIP 的概念并给予“绿灯”的阶段，足以让 EIP 作者继续进行开发。

## 摘要

根据以 EIP 为中心的升级模型，核心 EIP 的流程如下。
```
[ DRAFT ] -> [ ELLIGLE FOR INCLUSION ] -> [ IMPLEMENTATION ] -> [ TESTING ] -> [ ACCEPTED ] -> [ DEPLOYED ]
```

此 EIP 记录了所有核心开发者标记为**符合纳入标准**的所有 EIP。 通常，要达到此阶段，必须在 AllCoreDevs Call 上简要讨论 EIP，并通过大致的共识来推动将其转移到此阶段。 添加到此列表的任何内容都需要提供指向会议记录的链接，其中包含此讨论和决定。

**符合纳入标准**的要求是，代表主要客户端和生态系统利益相关者等的 AllCoreDevs：

- 对 EIP 持积极态度，
- 将接受（写得好的）PR 以将 EIP 包含到代码库中。
   - 这样就可以打开它进行测试……
   - ……但没有用于激活的实际区块号

## 动机

开发清晰的规范并向现有的 Ethereum 客户端发起 pull requests 需要大量的时间和资源投入。 *符合纳入标准*的状态是 Ethereum 核心开发者向 EIP 作者发出的信号，验证了 EIP 背后的想法，并确认进一步投入时间追求它是有价值的。
