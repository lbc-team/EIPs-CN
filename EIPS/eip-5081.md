## 摘要
此 EIP 添加了一种新的交易类型，其中包括基于区块号的过期时间。

## 动机

当用户发送 gas price 较低的交易 `tx0` 时，有时可能不足以执行。
一个常见的解决方案是用户使用相同的 nonce 和更高的 gas price 再次提交交易。

理论上，之前的 `tx0` 可以在任何时候被包含，除非具有完全相同 nonce 的 `tx` 已经被执行。

当网络拥塞时，gas price 很高，对于关键交易，用户可能会尝试比平均水平高得多的 gas price。
这导致 `tx0` 选择在平均情况下很容易执行。

如果用户已经使用具有不同 nonce 或来自另一个帐户的 `tx1` 来执行预期交易，
那么目前没有干净的方法来取消它，
除非签署一个新的 `tx0'`，它共享相同的 nonce，但具有更高的 gas fee，希望它能够*优先*于 `tx0` 执行。

鉴于 `tx0` 已经具有很高的 gas price，目前*优先* `tx0` 的方式可能既不可靠又非常昂贵。

### 参数
- `FORK_BLKNUM` = `TBD`
- `CHAIN_ID` = `TBD`
- `TX_TYPE` = TBD, > 0x02 ([EIP-1559](./eip-1559.md))


从 `FORK_BLOCK_NUMBER` 开始，引入了一个新的 [EIP-2718](./eip-2718.md) 交易，其 `TransactionType` = `TX_TYPE(TBD)`。

新交易的内在成本继承自 [EIP-2930](./eip-2930.md)，具体为 `21000 + 16 * non-zero calldata bytes + 4 * zero calldata bytes + 1900 * access list storage key count + 2400 * access list address count`。

此交易的 [EIP-2718](./eip-2718.md) `TransactionPayload` 为

```
rlp([chain_id, expire_by, nonce, max_priority_fee_per_gas, max_fee_per_gas, gas_limit, destination, amount, data, access_list, signature_y_parity, signature_r, signature_s])
```

`expire_by` 的定义是一个区块号，它是执行此交易的最后一个可能的区块。 任何区块号 `block_num > expire_by` 的区块都不得执行此交易。

所有其他字段的定义与 [EIP-1559](./eip-1559.md) 具有相同的含义

此交易的 `signature_y_parity, signature_r, signature_s` 元素表示对 `keccak256(0x02 || rlp([chain_id, expire_by, nonce, max_priority_fee_per_gas, max_fee_per_gas, gas_limit, destination, amount, data, access_list]))` 的 secp256k1 签名。

此交易的 [EIP-2718](./eip-2718.md) `ReceiptPayload` 是 `rlp([status, cumulative_transaction_gas_used, logs_bloom, logs])`。

## 安全注意事项

1. 如果 `current_block_num` 可用，客户端必须丢弃并停止传播/广播任何具有
`transaction_type == TX_TYPE` 且 `current_block_num > expire_by` 的交易

2. 建议但非必须，客户端应提供 `currentBlockNum`。 任何对过期 tx 区块进行 PoW 计算或传播此类区块的客户端本质上都会因为浪费工作而受到惩罚，从而减轻可能的拒绝服务攻击。

3. 建议但非必须，客户端应引入一个以 block_num 为单位的 `gossip_ttl` 作为安全网，以便仅在 `current_block_num + gossip_ttl <= expire_by` 时才传播 tx。 向后兼容性：对于没有 `current_block_num` 或 `gossip_ttl` 的节点，应假定它们为 `0`。
  
4. 建议但非必须，任何传播客户端都应根据其认为合适的网络环境正确扣除 `gossip_ttl`。
